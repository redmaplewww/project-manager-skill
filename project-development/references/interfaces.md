# 接口与数据契约

本参考用于工程包发现的真实接口和数据边界。先检查仓库已有格式、生成器和兼容策略，再选择契约形式。HTTP 可使用 OpenAPI；RPC、事件、消息、数据库 schema 和内部模块接口沿用项目对应的 IDL、schema 或代码级规范。不要为不存在的接口引入新技术。

## 通用契约字段

按适用情况明确：

- 接口名称、版本、提供方、调用方、所有者和生命周期。
- 目的、调用时机、同步/异步方式、输入和输出结构，字段类型、约束、可空性、默认值、单位和敏感级别。
- 鉴权/授权、租户或资源隔离、数据最小化和审计要求。
- 成功响应、业务错误和系统错误；错误码/分类、可重试性、用户/调用方处理方式。
- 超时、重试上限与退避、幂等键、重复请求、并发、顺序和一致性语义。
- 限流、容量、性能目标、依赖可用性和降级行为（仅在确实适用时）。
- 版本兼容、弃用通知、消费者迁移和旧/新版本并存策略。
- 日志、指标、追踪与脱敏规则；禁止把密钥或敏感载荷写入日志。
- 契约测试、生产者/消费者验证、样例请求和响应，以及对应验收场景。

避免“失败时重试”这类不可执行约定。说明重试的错误范围、次数、间隔、幂等保证和终止行为；若不重试，说明如何恢复或人工介入。

## 按接口类型补充

### HTTP/API

依据项目实际路由和协议记录方法、路径、参数、头、请求/响应 schema、状态码、认证、分页、排序、过滤、限流和兼容策略。已有 OpenAPI 时维护同一规范文件并运行仓库校验；不要同时手工维护一份相冲突的表格。

### 事件与消息

说明 topic/channel、生产者和消费者、事件 ID、事件时间、schema 版本、分区键/顺序、至少一次或至多一次等投递预期、重复与去重、死信/重放、兼容窗口和删除/保留策略。

### 数据库与持久化

说明实体所有者、主外键和唯一性、字段/索引、约束、生命周期、隔离、读写一致性、并发更新、迁移和回滚。迁移脚本必须可复核；破坏性变化要给出兼容部署顺序、备份/恢复和失败检测。示例数据不得含真实敏感信息。

### 内部模块接口

当接口跨模块维护边界时说明调用职责、允许依赖方向、输入输出、不变量、异常语义和测试边界。简单的同模块私有函数不需要单独契约文档。

## 契约变更门禁

变更前比较当前消费者和生产者，确认添加/删除/重命名字段、语义变化、默认值变化、鉴权变化、错误码变化和顺序/一致性变化的影响。破坏兼容的修改要安排版本迁移或消费者同步更新，并加入契约测试。

如果接口调整改变用户可观察行为、数据含义、权限或验收结果，停止相关实现并回到 project-manager 更新需求版本与确认；工程 agent 不能只以“技术优化”为由批准产品行为改变。
