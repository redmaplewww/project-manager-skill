# 工程标准参考

以下资料用于把传统软件工程原则映射到工程包和开发过程。它们是信息性参考；项目合同、法规、客户标准和仓库规范优先。除非项目要求正式符合性评估，否则不要把参考标准转换成全部必填清单，也不要声称“符合/认证”。

## 生命周期与需求

- **ISO/IEC/IEEE 12207:2026 — Software life cycle processes**：作为生命周期全景参考，把需求、设计、构建、验证、移交、运行、维护和退役按项目需要纳入计划。该标准允许并发、迭代、递归和增量应用，也不规定唯一开发模型；因此可以用于敏捷或增量交付，不代表必须走瀑布模型。
- **ISO/IEC/IEEE 29148:2018 — Requirements engineering**：作为需求质量、需求相关过程与信息项参考。用于检查工程输入是否可追踪、明确和可验证；产品范围和用户行为仍由 project-manager 确认。ISO 于 2024 年确认该版，2026 年已有新版草案在修订中；正式项目应重新检查 ISO 状态并遵循合同指定版次。

## 质量、测试与评审

- **ISO/IEC 25010:2023 — Product quality model**：用于从项目风险和用途中选择适用的产品质量属性，并转换为可验证的非功能条件。不要对每个功能无差别复制全部属性。
- **ISO/IEC/IEEE 29119-1:2022 — Software testing, Part 1: General concepts**：作为测试术语和过程设计的参考，支持把需求场景映射到静态、单元、集成、系统和验收证据。测试层级按架构和风险裁剪。
- **ISO/IEC 20246:2017 — Work product reviews**：作为评审流程、活动、技术和记录方式的参考。代码、设计、接口和迁移评审应记录范围、发现、决定和关闭状态；该版在 2022 年复审确认。

## 安全开发

- **NIST SP 800-218, SSDF Version 1.1**：作为可嵌入各类 SDLC 的安全开发实践参考。依据风险把安全要求、设计/依赖风险、代码验证和发布来源等内容放入工程包；不把参考框架说成自动安全保证或认证。

## 接口规格

- **OpenAPI Specification**：仅用于项目采用 OpenAPI 描述 HTTP API 的情况。编写或校验时先查看官方最新发布版及项目当前工具兼容性；沿用现有规范版本，不为局部功能擅自升级仓库工具链。

## 使用与维护

本映射的版次状态核对日期为 2026-10-22；项目要求正式遵循标准时，重新检查标准组织的最新目录和项目指定版次。

1. 先检查项目合同、法规、行业规范和组织过程要求；存在明确要求时，记录准确版次、适用范围、责任人和所需证据。
2. 将适用要求映射到工程包章节、工作包、源代码边界、验证活动和审计记录。
3. 明确裁剪依据、未适用项和无法获得的证据；不以“遵循最佳实践”替代验收标准。
4. 需要声称标准符合性时，先取得完整适用标准和项目批准的符合性评估范围，再逐条建立可审计证据；只看公开摘要不足以作出符合性结论。
