# 源码管理与审计

## Git 基线和改动保护

开始任何写入前检查仓库根目录、当前分支、HEAD、工作树状态、已暂存差异、未暂存差异和未跟踪文件。识别已有改动的归属和内容；不要覆盖、清理、重置或纳入不属于本任务的变更。发现并发或其他会话在改同一文件时，先读取最新状态并协同，不能盲目覆盖。

遵守仓库分支、提交信息、格式化和评审规则。按需求/工作包拆分可读改动，避免无关重排或未经证明的依赖升级。破坏性 Git 操作、提交、推送、合并、发布和部署均遵守现有授权。阶段交付与版本控制分别报告：项目明确要求提交作为交付条件时遵守；否则可完成有文件基线、实际差异、备份和证据的本地交付，同时注明未提交/未发布。无 Git 时不自行初始化，不把内部提交要求变成重复确认，也不把本地文件称为已提交或已发布。

实现过程中需要经常检查 diff 和状态，确保新增文件、删除文件、锁文件和生成文件都在预期范围。测试数据、日志和文档不得包含密钥或未脱敏的个人/客户信息。

## 源码审计流程

审计必须对照任务开始时保存的基线，检查本任务的暂存与未暂存差异、未跟踪文件，并查看必要的上下游调用面。先确定审计范围和证据，再做结论。

逐项检查：

- 需求与范围：每个行为都能映射到 REQ/WP/验收条件；有无越权功能、遗漏、错误默认值或不同场景行为冲突。
- 正确性和异常：边界值、空值、并发、超时、重复操作、失败恢复、幂等及资源释放是否符合契约。
- 接口与兼容：调用方/消费者、数据格式、权限、错误语义和版本兼容是否同步。
- 数据与迁移：数据归属、一致性、保留/删除、迁移顺序、备份和回滚是否明确。
- 安全与隐私：认证授权、输入处理、信任边界、依赖变更、秘密、敏感日志和数据泄露风险。
- 质量和测试：适当测试真实验证新增行为和反例；测试是否依赖实现细节、绕过真实边界或只验证 mock。
- 运维与文档：可诊断性、关键状态反馈、配置、升级/降级、恢复流程和文档是否与代码一致。
- 变更卫生：是否误改无关模块、生成文件、依赖锁、配置、格式或用户已有改动。

发现按仓库现行严重度规范排序；若没有规范，使用 Blocker、High、Medium、Low，并为每项列出文件/位置、证据、影响、复现或触发条件、建议修复和复核状态。没有发现时明确审计范围、已检查维度和测试缺口；有限 diff 审计不能称作全库安全审计。

## 完成交付

- 给出基线提交与最终差异摘要，并列出变更、删除和新增文件。
- 列出实际运行的检查及准确结果；明确跳过、失败或受环境限制的项目。
- 逐项列出未解决审计发现、风险与验收影响。
- 回写需求代码映射、工作包状态、工程包和证据索引。
- 确保工程包与代码处在同一审查分支/任务变更中，并遵循项目提交流程。未提交的文件不能报告为已持久化交付。
